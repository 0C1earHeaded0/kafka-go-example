# kafka-go-example
Learn how to build services that uses kafka

## Описание

### <a href='./docker-compose.yml#2'>confluentinc/cp-zookeeper</a>

Специализированная сборка (Docker-образ) распределенного сервиса координации Apache ZooKeeper, оптимизированная и поддерживаемая компанией Confluent в составе платформы Confluent Platform (коммерческой экосистемы вокруг Apache Kafka).

    Исторически он выполнял функцию внешнего хранилища метаданных и координатора для кластера брокеров Kafka, отвечая за консистентность, синхронизацию и живучесть всей системы.

В классической архитектуре Kafka (версии Confluent Platform до 7.9 включительно) ZooKeeper берет на себя четыре критически важные задачи:

- Выборы Контроллера (Controller Election): Механизм гарантирует, что в кластере всегда есть только один главный брокер (активный контроллер), который управляет распределением партиций и реплик.
- Управление метаданными кластера: Хранение информации о топиках, конфигурациях, количестве партиций, списках ACL (прав доступа) и расположении реплик.
- Регистрация участников (Cluster Membership): Отслеживание статуса брокеров («живой/умер»). Как только брокер отключается или появляется в сети, ZooKeeper мгновенно уведомляет об этом контроллер.
- Выборы лидеров партиций: Координация назначения лидирующих реплик (Leader) для обеспечения бесперебойного чтения и записи данных клиентами.

<br>

<b>

    В Confluent Platform 8.0 и новее служба ZooKeeper полностью удалена из дистрибутивов. Новые кластеры работают исключительно в режиме KRaft mode, где метаданные хранятся внутри самих брокеров Kafka, изолируя систему от внешних зависимостей. 

</b>
